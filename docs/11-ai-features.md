# 11 · AI Features

## 1. In plain words

PLOTSS uses AI in two places: to **understand a buyer's sentence** and to **help a seller write a clean description**. AI is a helper, never the decision-maker: it does not verify documents, approve listings or set prices.

The AI vendor is chosen by which key is present: **Groq Cloud** (`GROQ_API_KEY`, keys start with `gsk_`, default model `openai/gpt-oss-20b`) or **xAI Grok** (`XAI_API_KEY`, keys start with `xai-`). Both are called through a simple HTTPS request (OpenAI-compatible). If no key is set, or the AI fails, the site quietly falls back to plain rules/templates, so nothing breaks.

## 2. Feature list

| # | Feature | What it does | AI needed? | Status |
|---|---|---|---|---|
| 1 | **Natural-language search** | Turns "3 acre industrial land near Pune under 2Cr" into filters (city, category, budget, size, lease/rent, zone) shown as chips | Optional: rules handle common phrases; AI handles messy ones | ✅ |
| 2 | **Match score** | Percentage showing how well a listing fits the stated needs | No: simple weighted maths (city 30, category 20, budget 25, size 15, type 10) | ✅ |
| 3 | **Listing description assistant** | Rewrites the seller's notes into a clear description (professional / short / specification style) | Optional: template fallback | ✅ |
| 4 | **Area insight & price fairness** | Connectivity, clusters, price trend | Data-driven, not AI, in this release | 🟡 uses stored data |
| 4b | **AI risk screen for new listings** | Scores 0-100 risk using rules (basics, duplicates, price outliers, red-flag words) plus an optional Grok second opinion; shown to admins; passing listings get an "AI-screened" label. **Not a legal verification** | Optional | ✅ |
| 5 | Document checklist assistant | Suggests which documents a deal needs | — | 🔲 (the post flow lists standard documents) |
| 6 | Chat concierge (WhatsApp/on-site) | Answer questions, qualify leads | Yes | 🔲 |
| 7 | Photo tagging / quality check | Detect blurry or wrong photos | Yes | 🔲 |
| 8 | AI comparison summary | Written comparison of 2 to 3 listings | Yes | 🔲 |

## 3. How each AI call is protected

| Risk | Safeguard |
|---|---|
| Key theft | Key is server-only (`XAI_API_KEY`); never sent to the browser |
| Cost abuse | Rate limits: 20 searches/minute per visitor; 15 descriptions/hour per user; results cached (500 recent queries) |
| Wrong/invented output | The search AI must return JSON only; every field is **validated** (allowed cities/categories, positive numbers). Anything invalid is dropped and rules take over |
| Made-up facts in descriptions | The prompt says "use only the facts given; never invent amenities, distances, approvals or legal status". The seller sees and edits the text before submitting, and is reminded to check every fact |
| Long hangs | 20-second timeout; on failure fall back to template |
| Prompt injection (a user writes "ignore your instructions…") | The AI output is never executed or trusted: it is parsed into a fixed set of filters or shown as editable text |
| Privacy | Only the user's search text or listing facts are sent; no phone numbers, documents or account data |

## 4. Labelling

Anything written by AI carries the lime **AI** tag. Descriptions generated by the template fallback are **not** tagged AI.

## 5. Configuration

Add to `.env` (and to the hosting dashboard). Only one provider is needed. The keys are **secret**: never paste them in chat, email or screenshots (if one was shared, create a new key and delete the old one):

```
GROQ_API_KEY=gsk_...                 # Groq Cloud (used first if present)
GROQ_MODEL=openai/gpt-oss-20b        # any chat model your Groq account lists
# or
XAI_API_KEY=xai-...                  # xAI Grok
XAI_MODEL=grok-3-mini
```

Restart the server after changing them. Without a key: search uses rules, descriptions use a template (both fully functional). To see which models your Groq account offers, call `GET https://api.groq.com/openai/v1/models` with your key.

## 6. Quality checks (do before launch)

1. Try 20 real buyer sentences (in English and Hinglish) and compare chips with expectations.
2. Try tricky ones: "cheap land near highway", "5000 sqft godown Bhiwandi", "MIDC plot lease under 50 lakh".
3. Generate 10 descriptions and confirm none add facts that the notes did not contain.
4. Watch cost for a week and set a monthly cap in the xAI console.

## 7. Limitations (be honest with users)

- AI can misread a query; the chips make its understanding visible and removable.
- Multi-language (Hindi/Marathi/Gujarati) queries may be understood by the AI but the interface itself is English only for now.
- Only the cities listed in the database are supported.

## 8. Swapping the AI vendor

All AI calls go through one file (`src/lib/ai/llm.ts`). To add or change a vendor, edit the `provider()` function there; nothing else changes.
